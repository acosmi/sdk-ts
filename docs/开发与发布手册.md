# @acosmi/sdk-ts 开发与发布手册

> 适用版本: v1.0.0+
> 最后更新: 2026-05-25

## 1. 项目概览

`@acosmi/sdk-ts` 是 Acosmi 模型网关、SDK-facing Agent Run Gateway 与 compliance API 的 TypeScript SDK。**自 2026-05-22 起 TS SDK 成为主实现 / 事实标准**：Go SDK `acosmi-sdk-go` 暂停维护，本仓专注把 TS 做好做稳；待 TS 稳定后再从 TS 反向翻译补齐 Go。早期版本由 Go 端口而来，但布局与演进已不再受 Go 约束。

| 项目     | 值 |
| -------- | -- |
| 实现地位 | **主实现 / 事实标准**；Go SDK 暂停维护，后续从 TS 反向翻译 |
| 当前版本 | **2.18.0**（`ManagedModel.thinking_levels` 类型面对齐，加性、零行为变化，2026-08-29；近期链 2.14.0 inputModalities 开放值域 / 2.15.0 sources 四态 / 2.16.0 chat 超时预算下传 + 流式活性回调 / 2.17.0 桌面 loopback OAuth state 全路径闸，完整明细以 CHANGELOG 为唯一真源） |
| 版本策略 | TS 独立演进；wire-format / API 不兼容变更升 major（v2.0.0 已发，见 §10 / §18） |
| 主消费者 | `crabcode` (Anthropic 格式)、`crabdesign` / `crabclaw` 等下游产品 |
| 长期保留 | `OpenAIAdapter` (P0 红线，`crabclaw` 暂不用 TS 但保留双格式等地位) |
| LICENSE  | MIT — Copyright (c) 2026 Acosmi |

## 2. 仓库与发布拓扑

```
monorepo 真源 (acosmi/cloud-agent)           SDK 独立仓 (public)              npm 公开包
acosmi-sdk-ts/ 子目录 ── mirror-subtrees.yml ─→ github.com/acosmi/sdk-ts ──→ npmjs.com/@acosmi/sdk-ts
（push main 自动 subtree-split + force-push）   └── tag v* / dispatch 触发 release.yml
```

> 源码改动一律发生在 monorepo；公开仓只接收镜像与 tag。完整发版拓扑与触发方式见 §9.2.1。

**铁律**：
- SDK 是独立发布物，提交与 tag 只在 `acosmi-sdk-ts` 仓库内完成。
- 不把外层 monorepo 的 Java / Go / CFCA real provider 改动带入 SDK commit。
- 公开仓 history 和提交信息必须保持产品/SDK 语义，不包含协作工具或开发过程元数据。
- `docs/` 可放公开用户文档；内部 audit、证书材料、provider runbook 不进公开仓。

## 5. 编码规范

### TypeScript 风格（硬规则）

| 类别 | 规则 | 例 |
|------|------|----|
| 函数/方法 | **camelCase** | `discover`, `getAdapterForModel` |
| 类 / 接口 / 类型 | **PascalCase** | `Client`, `ServerMetadata`, `AnthropicAdapter` |
| Error 子类 | **PascalCase + Error 后缀** | `HTTPError`, `BusinessError`, `OrderTerminalError` |
| 常量 | **PascalCase**（前缀型）或 **UPPER_CASE** | `ErrDiscovery`, `ScopeAI`, `EventComplete` |
| 文件名 | **kebab-case** | `stream-meta.ts`, `bug-report.ts` |
| Wire-format 字段 | **snake_case**（与 Go json tag 严格对齐） | `preferred_format`, `created_at`, `max_tokens` |

### 不要使用的 Go-isms（硬禁止）

- ❌ **PascalCase 函数** — TS 公开 API 必须 camelCase（`AllScopes()` 是 Go 风格，改 `allScopes()`）
- ❌ **多返回值 `[T, Error]` 元组** — 用 `throw` + 类型化 Error 子类
- ❌ **`nil` 字面量** — 用 `null` / `undefined`
- ❌ **`: any`** — 优先 `: unknown` 或精确类型
- ❌ **Go 关键字识别符**：`func`, `package`, `chan`, `defer`, `goroutine`
- ❌ **指针风格 `T | null`** — 用 optional `?: T`（除非 wire-format 必须）
- ❌ **`fmt.Sprintf` / `fmt.Errorf` / `log.Println`** — 用模板字符串 / `new Error()` / `console`

### 跨语言契约印记（TS→Go 反向翻译对照基准，不许改）

TS 现为主实现，**文件级与 Go 1:1 对齐的约束已作废** —— `src/` 布局完全自由（见 §4
域文件夹结构）。但以下跨语言契约仍是将来把 TS 反向翻译为 Go 时的对照基准，必须保留：

- ✅ **snake_case wire-format 字段名** — wire 协议契约（50+ struct 已对齐），不可漂移
- ✅ **符号名跨语言一致** — 导出的类型 / 方法 / 错误名是 TS↔Go 对照锚点
- ✅ **bug-for-bug 行为对齐**（e.g. retry POST=false 默认，sanitize thinking 硬豁免）
- ✅ **ISO 8601 字符串时间** — 与 Go RFC3339 wire-compat
- ✅ **金额按域分两种约定** — ①钱包/展示类（如 `WalletStats.balance`）用 **json.Number string**（十进制元，避免 JS number 精度损失）；②finance 域（发票/退款/对公转账）用 **`amountFen` 分单位整数 `number`**（如 `amountFen`/`taxAmountFen`/`requestedAmountFen`，2^53 内无浮点风险）。**不要写"金额一律 string"**——会与 finance 实际类型矛盾
- ✅ **双 adapter 等地位** — `AnthropicAdapter` + `OpenAIAdapter` P0 红线，不可降级
- ✅ **已有端口代码的 "端口自 X.go" 溯源注释** — 历史对照保留；compliance、对外鉴权层等
  新域本就无 Go 对应物，不写该注释

### TS 不可避免的偏移（与 Go 不 1:1）

| 维度 | Go | TS |
|------|----|----|
| 错误处理 | `(val, err)` 多返回值 | `throw` + 类型化 Error 子类 |
| 上下文取消 | `context.Context` | `AbortSignal` |
| 流返回 | `(eventCh, errCh chan)` | `AsyncIterable<StreamEvent>` |
| 锁 | `sync.Mutex` | Promise chain (`this.mu`) |
| IO | 同步 `os.ReadFile` | `fs/promises` async |
| Token Store 持久化 | 同步 file IO | `async` Save/Load/Clear |

### Agent Runs 公开 API 范围

从 v1.1.0 起，SDK 不再只是模型网关客户端，还包含下游产品可用的云端智能体任务协议：

- `client.agentRuns.create(req, signal?)`
- `client.agentRuns.stream(runId, opts?, signal?)`
- `client.agentRuns.run(req, opts?, signal?)`
- `client.agentRuns.cancel(runId, signal?)`
- `client.agentRuns.get(runId, signal?)`
- `client.agentRuns.listArtifacts(runId, signal?)`
- `client.agentRuns.downloadArtifact(runId, artifactId, signal?)`
- `client.agentRuns.submitLocalToolResult(runId, result, signal?)`
- `client.agentRuns.runWithLocalTools(req, handlers, opts?, signal?)`

**远程控制（v2.1，CrabCode remote-control）** — 同属 `agentRuns` 命名空间，但事件协议独立（契约 §4 的 11 事件，不复用 `stream` 旧 union）：

- `client.agentRuns.createRemoteRun(req, signal?)` — `req.runtime` 固定 `'crabcode_remote'`，`runner` + `adapter` 必填；v2.7.0 起支持 `byokCredentialRef`（仅 cloud runner）与 metadata 约定键 `title`/`workspace`（契约 §18.3 r4）。
- `client.agentRuns.streamRemoteControl(runId, signal?)` — **无 options 参数**（`error` 恒非终结、`done`/`settle` 终结、从不抛异常）。
- **远控管理面（v2.7.0，契约 §18.1 附录 A）**：`list(opts?)`（runtime/status 过滤分页，信封 `{records,total,page,pageSize}`）、`submitPermissionResult(runId, {requestId, decision, reason?})`（仅 approved|rejected）、`submitUserMessage(runId, {content, requestId?})`（≤64KB，role 服务端硬编码）、`revealRemoteToken(runId)`（一次性 token，仅 desktop runner，永不落浏览器存储）。
- **BYOK（v2.7.0，契约 §18.2）**：`client.crabcodeByok.list/create/rotate/revoke` —— `/crabcode/byok-credentials`，`remote_control` scope；明文一次性提交，响应恒 masked。
- helper：`parseRemoteControlEvent(raw)`（wire→强类型，未知 type 返回 null）、`isTerminalRemoteEvent(ev)`。
- `chatbridge`（v2.7.0 起 Phase 7B 管理面落地）：`client.chatBridge.createIntegration/listIntegrations/getIntegration/updateIntegrationStatus + storeCredential/listCredentials/rotateCredential/revokeCredential`（请求 snake_case 由 SDK 转换、响应 camelCase；scope 三档 `chat_bridge:read`/`:write`/`:rotate`）。类型 + 守卫（`isPlatform` / `isRegion` / `isChannelInboundEvent` / `asCredentialRef`）沿用 v2.1 骨架。平台 webhook adapter（验签/收发）是 Phase 8 后端工作，平台 SDK 依赖留在独立 adapter 包，禁进主包。

**会员订阅查询（v2.6，C 端会员体系）** — `subscription` 命名空间新增：

- `client.subscription.getMembership(signal?)` — 当前会员视图（**取代** `listUserSubscriptions`，后者已废弃）。
- `client.subscription.getSubscriptionTier(signal?)` — 订阅档位。
- `client.subscription.subscriptionPrecheck(req, signal?)` — 升级前置校验。
- 同版本 `ManagedModel` 新增档位门控字段 `locked` / `freeTier` / `minPlanTier` / `chatRuntimeSupported` / `defaultToolIds`，供 C 端聊天模型选择器按会员档位加锁 / 分区。废弃 `ModelCoefficient` / `listCoefficients`（系数退役恒空）与 `ManagedModel.pricePerMTok` / `isDefault`（公开端点不返回）。

红线：
- 下游产品禁止直连 Nexus 内部 `/api/v4/chat/completions` 或 `/api/v4/managed-models/:id/...` 来实现智能体循环。
- Agent Runs wire-format 使用 snake_case；SDK public API 使用 camelCase。
- **远控 wire 约定按平面分（契约 §12）**：remote-control 平面 = snake_case + 时长整数毫秒（`approval_timeout_ms`，**禁** Go `time.Duration` 上 wire——会被当纳秒）；chatbridge 资源视图平面 = camelCase。两平面不可混用。
- **远控事件唯一序列化出口**：后端 `RemoteSessionEvent.ToWire()` 出扁平 snake_case 帧（`type`+`seq`+字段同级）；改动远控事件字段/单位/形状，必须同步更新跨语言金标 fixtures（后端 `remotecontrol/testdata/wire_golden.json` ⇄ SDK `test/remote-control-wire-golden.test.ts`），任一端漂移即红——这是 P1-1 同类分裂的护栏。
- **远控专用 scope**：`remote_control`（+ 3 子 scope）绝不复用 `models:chat`/`ai`，且 **不进 `allScopes()`**；`ai` 展开列表禁加入任何 `remote_control` 子项（隐式获权后门）。
- **secret 边界（契约 §16）**：chatbridge 平台 secret 只入上游 vault；SDK 公共面只见 `CredentialRef` + fingerprint + 脱敏 metadata，`ChatCredentialPublic` 编译期无密文字段。
- Agent Runs 服务端状态必须按 `tenantId + userId` 隔离并持久化；run/SSE event/artifact/local-tool-result 不能只放进进程内存。
- Agent Runs 执行必须接入统一 entitlement hold/settle/release 链路；settle 失败必须进入既有 pending settlement 补偿机制。
- Agent Runs 结算只能使用 provider/ADK 透传的 `exact: true` usage；不得用字符数、输入长度或其他估算 token 扣费。provider usage 缺失时必须 release hold，并向 stream 返回稳定的 `usage_missing_released` settlement 状态。
- `create`、`submitLocalToolResult` 等可能产生副作用的 POST 遇到 401 不自动 refresh 后重放，避免重复创建或重复计费；GET/stream/download 这类安全查询允许单次 refresh 重试。
- SDK 不内置 CrabDesign/CrabCode/CrabClaw 专属本地文件读取逻辑；`local_tool_request` 只定义协议，handler 必须由下游显式传入；`allowedTools` 使用 ASCII function name。

### InputModality + 桌面视觉理解 sidecar 契约（v1.2.0）

从 v1.2.0 起，SDK 暴露上游 `ManagedModel` 的输入模态字段 + 桌面视觉理解 sidecar capability，供 CrabCode desktop automation / computer-use 通过 catalog（而非模型名 substring）选模型：

**类型契约**：

- `InputModality = 'text' | 'image'`（严格白名单）
- `ManagedModel.inputModalities?: InputModality[]` — 模型可接收的用户输入模态；`undefined` = 未声明（保守按 text-only / unknown 处理）
- `ModelCapabilities.supports_desktop_visual_understanding?: boolean` — 模型是否被运营标记为桌面截图解析 sidecar（输入 screenshot，输出 UI 结构化描述）

**4 个 catalog helper**（`src/models/model-helpers.ts`）：

- `modelSupportsInputModality(model, modality): boolean`
- `modelSupportsImageInput(model): boolean`
- `findFirstModelByInputModality(models, modality): ManagedModel | null` — 按 catalog 顺序，跳过 `isEnabled === false`
- `findDesktopVisualUnderstandingModel(models): ManagedModel | null` — 选择规则：`isEnabled !== false` + `supports_desktop_visual_understanding === true` + `inputModalities` 含 `image` + `isDefault` 优先 / 否则 catalog 顺序第一

**协议归一化**：

- `listModels` / `listModelsWithStatus` 会归一化上游 snake_case `input_modalities` → camelCase `inputModalities`（兼容老网关）
- 同时存在 camelCase + snake_case 时 camelCase 胜
- `zeroModelCapabilities()` 显式置 `supports_desktop_visual_understanding: false`，避免 `undefined` 误判

**红线（严禁违反）**：

- 客户端**不得**在本地硬编码模型名做能力推断（如检测 modelId 含 "vision"）；一切视觉模型选择必须来自 SDK catalog 字段
- 上游 `ManagedModel` 缺失 `inputModalities` 时，SDK 保留 `undefined`，**不**自动补 `['text']` — 调用方必须保守按 text-only / unknown 处理，**严禁默认假设支持 image**
- 网关后端强约束：`supports_desktop_visual_understanding=true` 必须 `inputModalities` 含 `image`（handler 400 拒绝错配置）
- `inputModalities` 与 `capabilities.supports_desktop_visual_understanding` 是正交两件事：前者描述"模型能不能吃图"，后者描述"运营是否把该模型标为桌面 UI 解析专用 sidecar"

**新增单测**：

- `test/list-models-input-modalities.test.ts` — listModels snake/camel 归一化 + undefined 保留 8 case
- `test/model-helpers.test.ts` — 4 个 helper + isEnabled/isDefault 优先级 15 case

### Compliance SDK 契约（v1.3.0）

从 v1.3.0 起，SDK 暴露 `client.compliance` 子客户端，覆盖时间章、电子证据、
证据包、报告、合同签署 envelope、用印审批和 provider request 脱敏状态轮询。

**🔑 两条传输约定（务必先读 —— 决定一个方法的 path 该不该带 `/api` 前缀）**

SDK 的业务 path 经 `apiURL()` 统一前置 `/api/v4`。但后端有两类落点，对应两种 path 写法，**写错会 404 或反而"修对成 404"**：

1. **网关反代的公开端点 → path 不带 `/api`**。例：`subscription`/`pricing`/`products` 用 `/distribution/public/...`。Go 网关（`nexus-v4` `routes_business.go` `registerDistributionPublicProxy`）匹配 `/api/v4/distribution/public/**`、`TrimPrefix("/api/v4")` 后转发到 tk-dist。**只有 `/distribution/public/**` 在网关注册**，其它 distribution/admin 子路径网关无路由。
2. **直连 tk-dist 的同源代理端点 → path 带 `/api`（与后端控制器 `@RequestMapping("/api/...")` 逐字一致）**。例：`casehall.getMyLawyerCredentialStatus` 用 `/api/casehall/lawyer-credentials/my`、`finance.*` 用 `/api/distribution/finance/...`、`enterprise.*` 用 `/api/admin/...` 或 `/api/distribution/enterprise/kyc/...`。这些经消费域 nginx 的 **casehall 式直连规则**（`location /api/v4/api/casehall/ → http://127.0.0.1:48080/api/casehall/`，剥 `/api/v4` 直连 tk-dist `:48080`，与 `/admin-api` 同款）落地，最终 URL 出现「双 `/api`」(`/api/v4/api/...`) **是正确的**。
   - 生产实证（2026-05-31）：`sign.zhonglvbao.com/api/v4/api/casehall/lawyer-credentials/my` → 401（可达，待鉴权）；去掉 `/api` 的 `…/api/v4/casehall/...` → 404。
   - **新接入第 2 类业务方法时**：SDK 用后端控制器全 `/api/...` 路径，并在该方法的**消费部署域** nginx 补一条 casehall 式 `location /api/v4/api/<前缀>/ → :48080/api/<前缀>/`。**finance/enterprise 当前无前端消费**，路径已对、等接线时补 nginx 即可。
   - casehall 的 `listLawyers`/`getMyCases` 等 `/casehall/app|me/...`（不带 `/api`）方法对应**后端 consumer 端点尚未实现**（已标 `@experimental`），调用会 404；不是 path 前缀问题，是下游后端缺失。

**公开 API 边界**：

- `Config.complianceBaseURL` 默认 `${serverURL}/admin-api`，不复用 `/api/v4`。
- `src/compliance/client.ts` 只发送 Acosmi 公共 DTO，不发送 provider 选择字段。
- compliance 类型文件（`src/compliance/**/types.ts` —— 各子域 `evidence/timestamp/signing/...`
  的 `types.ts` 及共享 `src/compliance/types.ts`）不得暴露 provider
  product/user/transaction/project/seal-provider 字段。
- `src/compliance/errors.ts` 只按 Java numeric `BusinessError.code` 分类，不从 message 文案做正则。
- `src/index.ts` 以 `export * from './compliance'` 导出 compliance 域；`src/compliance/index.ts`
  barrel 从 `./client` re-export `ComplianceClient`，该 re-export 即加载 `client.ts`，
  其 `Client.prototype` 的 `compliance` getter declaration-merging 随 barrel 一并生效。

**写操作红线**：

- POST/PUT/DELETE 不自动 retry。
- 写操作 401 不 refresh + replay；调用方重新认证后用同一 `Idempotency-Key` 恢复。
- GET 读路径可以做单次 401 refresh retry。

**安全红线**：

  JKS/PFX/P12、P7、zip、jar、口令、provider raw payload 或 callback billing commit payload。

- TS SDK 只申请 scope、发送公共 DTO、分类公开错误码并轮询脱敏状态。

`release.yml` 与 tag 都只在公开仓。所以「改代码」在 monorepo、「发版」在公开仓，
中间隔着一次镜像同步。

**发版入口：用 `workflow_dispatch`，不要依赖 tag push。**

```bash
# 1) 确认镜像已同步到要发的内容
gh api repos/acosmi/sdk-ts/contents/package.json --jq .content | base64 -d | grep -m1 version
SHA=$(gh api repos/acosmi/sdk-ts/commits/main --jq .sha)

# 2) 在公开仓打 tag（仍要打——Release 页面与 npm provenance 都指向它）
git clone https://github.com/acosmi/sdk-ts.git tmp && cd tmp
git tag vX.Y.Z "$SHA" && git push origin vX.Y.Z

# 3) 触发发布
gh workflow run release.yml --repo acosmi/sdk-ts --ref vX.Y.Z
gh run watch <run-id> --repo acosmi/sdk-ts
```

> **为什么用 `workflow_dispatch` 而不是 tag push**：v2.14.0 发版时，**连续 5 次**
> 创建 tag（REST 建 ref ×1、浅仓 `git push` ×3、完整 clone `git push` ×1）**都没有
> 产生任何 workflow run**。当时结论写的是「成因未定位」—— 那是错的，2026-08-02
> 已用对照实验查清。
>
> **根因：GitHub 扫描 commit message 全文，不只是标题行。** 被 tag 的 commit 只要
> **任何一行**出现 skip 指令字面量（`[skip ci]` / `[ci skip]` / `[no ci]` /
> `[skip actions]` / `[actions skip]`），该次 push 就被静默跳过 —— tag push 也是
> push 事件。跳过时不报错、不留 run、Actions 页面上什么都没有。而 subtree split
> **原样保留 monorepo 的 commit message**，monorepo 又为省 CI 额度常带该指令，
> 标记就这么被一路带进公开仓，落在待发版的那个 commit 上。
>
> 5 次尝试全部命中：整个尝试窗口内公开仓 main 的 HEAD 依次是 `ee2a3a8a` →
> `b72efe62` → `73603e52` → `fd7cfd48`，**四个 commit 的 message 里都含该字面量**。
> 前两个是标题行里的真指令（从 monorepo 带过来的）；后两个标题行是干净的，
> 但**正文里为了记录这个现象而引用了该字面量** —— 原话是「被 tag 的 commit
> message 不含 …」「本 commit 不带 …」。**否认它的那句话本身包含了它。**
> 这也正是当初判定「已排除 skip 指令」的由来：人只看标题行，GitHub 匹配全文。
>
> **对照实验**（2026-08-02 13:50Z；同一分钟、同一 `git push`、同一 workflow，
> 唯一变量是被 tag 的 commit）：
>
> | 探针 tag | 指向 commit | 字面量位置 | 结果 |
> |---|---|---|---|
> | `v0.0.0-probe-control` | `9f17a8a8` | 无 | **2 秒内产生 run**，一路绿到 `Publish to npm` 才因版本已存在而失败 |
> | `v0.0.0-probe-skipci` | `73603e52` | 仅正文 | **零 run** |
>
> 两个 tag 均已确认推到远端；实验后都已删除。
>
> **硬规则：commit message 里永远不要出现那个方括号字面量，哪怕是在讨论、引用或
> 否认它。** 需要提及时写成不带方括号的 `skip-ci 指令`。**文件正文不受影响** ——
> GitHub 只扫 commit message，所以本文档里写全字面量是安全的。
>
> **仍以 `workflow_dispatch` 为推荐入口**，理由不是 tag push 坏了（它没坏，上面
> 的对照组证明此刻完全正常），而是 dispatch **不是 push 事件、对这一整类失败
> 结构性免疫**；而 monorepo 常规使用 skip 指令，靠人每次记得检查 message 全文
> 不可靠。tag 仍然要打（Release 页面与 npm provenance 都锚定它），只是不靠它触发。

**一条被证伪的旁证，别再当信号用**：当时观察到「仓库事件流里连 `CreateEvent` 都
没有」，被当成「tag 根本没注册上」的旁证。那是 events API 的假象 —— 发版成功的
`v2.14.0` 那次 tag 创建同样查不到 `CreateEvent`（而 tag 删除的 `DeleteEvent` 条条
都在）。**tag 的 `CreateEvent` 在这个仓从来不出现，不能用它判断 tag push 是否生效。**

**一条至今未验证的说法**：「REST 建 ref（`gh api .../git/refs -X POST`）只产生
`create` 事件、不产生 `push` 事件，故对 `on: push: tags` 无效」。本次唯一用 REST 的
那次尝试已被 skip 指令完整解释，**没有为这个说法留下任何证据**；此前手册断言它成立
是误写。要么实测，要么直接用 `git push` 绕开这个问题。

**打 tag / dispatch 前的落地检查**（`npm publish` 之前还有 typecheck / lint / test /
build / docs 五道，本地先跑绿，别拿发版流水线试错）：

```bash
npm run typecheck && npm run lint && npm run build && npm run test:pack && npm run docs
```

> 前一步失败。已改朴素 `string` —— 补全的价值在**书写**字面量，而那个类型描述的是
> 从目录**读到**的数据，技巧本就不必要。
>

## 10. 版本号策略

**自 2026-05-22 起版本策略以 TS 为准**：TS SDK 是主实现，独立演进；Go SDK `acosmi-sdk-go`
暂停维护，原"Go + TS 主版本号联动"约束已挂起，TS 不再等 Go 对齐版本号。

- **minor**（x.y.0）：新业务方法 / 新域 / 向后兼容的协议扩展
- **patch**（x.y.z）：bug fix、文档、内部 refactor、packaging fix
- **major**（x.0.0）：wire-format 不兼容变更、API 移除、TokenStore 接口变化、后端契约 BREAKING

**实例 — v2.0.0（2026-05-25）**：商品化 P1-P7 Phase 3 复核后 SDK 首次 major bump。SDK 公开类型 / 方法签名零移除、零改名，但**网关后端契约 BREAKING**：
1. `SensitiveSerializer` 取消 `ROLE_ADMIN` → `platform_admin` 别名 fail-OPEN，统一收敛为 4 角色严格白名单（`platform_admin` / `s2s` / `lawyer` / `consumer`），违反即返回脱敏值。
2. admin 写端点错误码从 `200 + {ok:false, code}` 改为 HTTP 状态码（`403` 鉴权不足 / `404` 资源不存在 / `501` `NOT_CONFIGURED_CODE`）。
3. PII 字段（如 `Invoice.taxId` / 律师执照号）落盘从"应用层脱敏"升级为"AES-GCM 真加密 + AAD field binding + `keyVersion` v1/v2 协议"，运行时 transparent，但消费方读取行为受 §1 角色严格化影响。

**实例 — v2.0.1（2026-05-25）**：纯 packaging fix。`package.json.files` 数组补 `docs/pii-role-matrix.md` + `docs/开发与发布手册.md`，让 v2.0.0 引入的两个 docs 随 npm tarball 下发。无源码改动，从 v2.0.0 升级无需 review。教训：**任何 v.major.0 BREAKING 发版同时必须自查 `files` 数组**——见 §18 v2.0.0 复盘。

> 历史背景：v1.0.0 时曾约定 Go + TS 主版本号同步、patch 各自独立。该联动机制因 Go SDK
> 暂停维护已挂起。将来 Go SDK 从 TS 反向翻译重启时（见 §11、计划 §3），版本对齐策略需
> 重新评估，本节届时一并修订。

## 11. Go SDK 反向翻译流程（当前暂停）

> **状态：暂停**。本节描述的是将来 Go SDK 重启时的方向，目前不执行。

历史上本节是「Go SDK 升级 → 镜像到 TS」的同步流程；自 2026-05-22 起 TS 成为主实现、
Go SDK 暂停维护，该 Go→TS 镜像流程已不再适用。

未来方向（计划 §3）：待 TS SDK 稳定后，从 **TS 反向翻译补齐 Go**，方向是 TS→Go。
反向翻译以 §5「跨语言契约印记」为基准：

- 导出的类型 / 方法 / 错误**符号名**跨语言一致，作为 TS↔Go 对照锚点
- **snake_case wire-format 字段名**严格一致（wire 协议契约不可漂移）
- **bug-for-bug 行为对齐**（retry POST=false 默认、sanitize thinking 硬豁免等）
- 翻译时引入 Go 端不可避免的偏移（`(val, err)` 多返回值、`context.Context`、channel 流等，见 §5 偏移表的反向）

在 Go SDK 重启反向翻译之前，TS SDK 的发版只走 §9.2，不需要任何 Go 侧同步动作。

## 12. 故障排查

### 12.1 npm publish 失败

| 错误 | 原因 | 排查 |
|------|------|------|
| `403 Forbidden` "Two-factor authentication or granular access token with bypass 2fa enabled is required" | Token 没开 bypass 2FA | 重建 Granular token，**勾选 "Bypass two-factor authentication"**；或换 Classic Automation token |
| `403 Forbidden`（其他） | `NPM_TOKEN` secret 失效 / 包名权限不够 | 重建 token，确保 packages 选了 `@acosmi/sdk-ts` |
| `EPUBLISHCONFLICT` / `cannot publish over the previously published versions` | 没升 version | 升 `package.json` `"version"` |
| `package private` | `package.json` 还有 `"private": true` | 删掉或改 `false` |
| `provenance attestation failed` | 仓库 visibility / OIDC 配置不对 | workflow 里**去掉** `--provenance` flag |
| `404 Not Found` 在 publish 时 | 包名拼错或 `publishConfig.access` 缺 | `package.json` 加 `"publishConfig": { "access": "public" }` |

### 12.2 typecheck 失败

- 改了某个域的 wire-format 类型（`src/models/types.ts` / `src/compliance/**/types.ts` 等）→ 检查所有 caller
- import 路径错 → `npm run typecheck` 输出文件:行号
- TS strict 默认开 → 看具体 error，不要图方便加 `as any`

### 12.3 test 失败

- `routing.test.ts` 红 = **P0 红线破坏，严重停车**，立刻回滚
- `history.test.ts` 红 = sanitize 行为漂移（检查 thinking 豁免 / tool_use_id 联动）
- `anthropic-build.test.ts` 红 = adapter buildRequestBody 行为变了（确认是有意的契约变更，而非回归）

### 12.4 公开仓 push 失败

| 错误 | 排查 |
|------|------|
| `Host key verification failed` | 把 remote URL 从 `git@github.com:` 改成 `https://github.com/` |
| `Updates were rejected because the remote contains work` | 先 `git fetch` + `git pull --ff-only`；只有维护者明确要重写历史时才 force push |
| `This repository moved. Please use the new location` | 仓库被 transfer 了，更新 remote URL（见原始 enterprise repo） |
| GitHub Contributors 显示异常作者 | 检查本地 `git config user.name/user.email`，必要时修正后重新提交 |

### 12.5 下游 crabcode 报 type / 模块 缺失

- 同日 — audit Part 2: `npm i @acosmi/sdk-ts@1.0.1` consumer 视角实拉 + smoke `tsc --noEmit` 全绿，9 处 declare module 在 dist/node/index.d.ts 行 548/571/592/601/645/654/677/720/761 全包名
- 同日 — `npm deprecate @acosmi/sdk-ts@1.0.0 'broken packaging, use 1.0.1+'`（手动单独跑，CI 不含）

### 翻车的两层根因

| 层 | 现象 | 根因 |
| --- | --- | --- |
| Layer 1 — packaging | bun / Node ESM `Cannot find module '@acosmi/sdk-ts'` | `tsup.config.ts` 无 `outExtension`（默认输出 `.js + .cjs`），`package.json.exports` 8 处写死 `.mjs` 引用，两侧无对账 |
| Layer 2 — d.ts augmentation | consumer 项目 `getBalance` / `submitBugReport` 等 50+ 方法 TS2339 | 9 处 `declare module` 用相对路径（`'../client'` / `'./client'`），tsup 打包 d.ts 不做 path rewrite，consumer 视角下相对路径指向不存在的文件 |
| 流程根因 | publish 前没拦截 | `prepublishOnly` 仅跑源码侧（typecheck / lint / vitest / build），不验证 **packed product 在 consumer 视角能否解析** |

### 修复点

- **Layer 1**：`tsup.config.ts` 三 entry 显式 `outExtension: ({ format }) => ({ js: format === 'esm' ? '.mjs' : '.cjs' })`
- **Layer 2**：9 处 `declare module '../client'` / `'./client'` → `declare module '@acosmi/sdk-ts'`；附加 `tsconfig.json` 的 `paths` 让源码 typecheck self-reference
- **流程**：新增 `scripts/smoke-pack.mjs` + `prepublishOnly` 末尾 `&& npm run test:pack`

### 烟测脚本设计要点

- **跨平台**：用 `spawnSync` 不用 `exec/execSync`（无 shell injection）；`shell: isWin`（Node 20.12+ Windows 安全限制 CVE-2024-27980 修复后跑 `.cmd` 必需）
- **隔离 consumer**：`mkdtempSync(os.tmpdir())` 临时目录，不污染 caller 的 `node_modules`
- **覆盖 9 处 augmentation**：`smoke.ts` 内调用每个 `declare module` 文件至少一个 method（`getBalance` / `getWalletStats` / `listTokenPackages` / `listNotifications` / `listTools` / `browseSkillStore` / `submitBugReport` / `applyRequestSanitizers` / WS `connect` typeof 验证）
- **失败保留**：smoke 失败时保留临时目录供调试；成功才清理

### 未来发版前必读
